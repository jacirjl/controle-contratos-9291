Arquitetura de Persistência Híbrida • Event Store Cronológico + Vector DB + Watermark SHA-256

Solução Implementada: Banco Híbrido (db/contrato_9291.sqlite) com Ingestão Incremental Append-Only (Economia de 100% dos Tokens nas Páginas Anteriores)

Como os processos do e-Protocolo Paraná são estritamente cumulativos (append-only) — isto é, quando você baixa um PDF atualizado, as páginas 1..N permanecem intactas e apenas as novas páginas N+1..M são anexadas ao final — implementamos uma arquitetura em 3 camadas acopladas no arquivo local c:\ProgsAntigravity\Contratos\db\contrato_9291.sqlite:

1. Watermark SHA-256 por Página (Delta)

A tabela document_watermarks guarda last_ingested_page (N) e o hash SHA-256 da página 1 e da página N de cada PDF. Ao atualizar os arquivos, o motor valida o hash da página N em 0,02s e processa com IA/Embeddings somente da página N+1 até M.

2. Event Store Cronológico (B-Tree)

A tabela chronological_events armazena cada marco das 10 etapas com data normalizada ISO-8601 (YYYY-MM-DD) e índice composto (event_date ASC, step_number ASC), garantindo consulta cronológica instantânea sem reprocessar texto.

3. Vector Store + Cache IA por Página

A tabela vector_chunks guarda para cada uma das 3.308 páginas o embedding vetorial normalizado (384 dims), o resumo pré-extraído pela IA (ai_summary) e as entidades JSON (valores R$, NFs, USN, UST, datas).
